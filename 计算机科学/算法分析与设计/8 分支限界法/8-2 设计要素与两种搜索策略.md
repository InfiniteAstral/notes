# 8.2 设计要素与两种搜索策略

## 8.2.1 设计要素

分支限界法的设计可以归纳为五个要素：

1. **定义解空间**：问题解向量、每个分量的取值集合；
2. **构造解空间树**：子集树、排列树或 $m$ 叉树；
3. **判断多米诺性质**：保证“前缀不合法 ⇒ 扩展后也不合法”，剪枝才安全；
4. **确定剪枝函数与界函数**：约束函数保证可行性，界函数保证最优性；
5. **选择搜索策略**：FIFO 队列、LIFO 栈或优先队列。

| 要素 | 作用 | 示例（0-1 背包） |
| :--- | :--- | :--- |
| 解向量 | 描述一个解 | $x_i\in\{0,1\}$ |
| 解空间树 | 组织所有候选解 | 子集树 |
| 约束函数 | 剪掉不可行分支 | $cw+w_i\le c$ |
| 界函数 | 剪掉不可能更优的分支 | $UB=cv+\text{剩余分数背包}$ |
| 搜索策略 | 决定扩展顺序 | 按 $UB$ 最大优先 |

## 8.2.2 通用框架

```text
Q = {q0}                       // 活结点表，初始为根
while Q 非空
    q ← select(Q)              // 按策略选一个扩展结点
    Q.remove(q)
    for each child c of q
        if feasible(c) and promising(c)
            Q.add(c)
return best
```

框架很简单，难点全在 `select`（搜索策略）与 `promising`（界函数）。

## 8.2.3 结点的数据结构

分支限界法需要在结点中保存“从根到当前结点的决策路径”以及“当前状态”，以便计算界、构造最优解。

```java
class Node {
    int level;          // 所在层（已确定的决策个数）
    Node parent;        // 父结点，用于回溯构造解
    boolean leftChild;  // 是否为左儿子（决定 x[level] 的取值）
    int cw, cv;         // 当前重量、价值（以背包为例）
    double bound;       // 上界/下界
}
```

::: tip 为什么不用数组存路径？
每个结点都复制一份长度为 $n$ 的路径，空间会变成 $O(n\cdot 2^n)$。用 `parent` 指针 + `leftChild` 标记，每个结点只存 $O(1)$ 的额外信息，最后从叶子沿 `parent` 回溯即可得到完整解，空间降到 $O(2^n)$。
:::

## 8.2.4 策略一：FIFO 队列式

FIFO（先进先出）队列式分支限界法按**广度优先**顺序扩展：先扩展第 1 层所有结点，再第 2 层……

为了知道当前扩展到第几层，常用**层标记**（如 `null` 或 `-1`）：

```java
Queue<Node> q = new LinkedList<>();
q.add(root);
q.add(null);                 // 第 1 层结束标记

while (!q.isEmpty()) {
    Node node = q.poll();
    if (node == null) {      // 一层结束
        if (q.isEmpty()) break;
        q.add(null);         // 下一层结束标记
        continue;
    }
    // 扩展 node 的儿子
    for (Node child : expand(node)) {
        if (feasible(child) && promising(child))
            q.add(child);
    }
}
```

### 特点

- 实现简单，天然按层推进；
- 需要一个“层标记”来区分层；
- 找到的第一个叶子不一定最优，必须搜完所有可能；
- 空间 worst-case $O(2^n)$，因为同一层的结点可能全部存活。

## 8.2.5 策略二：优先队列式

优先队列式（最佳优先）分支限界法按**界的优劣**扩展：极大化问题按 $UB$ 从大到小，极小化问题按 $LB$ 从小到大。

```java
PriorityQueue<Node> heap = new PriorityQueue<>(
    (a, b) -> Double.compare(b.bound, a.bound));   // 最大堆
heap.add(root);

while (!heap.isEmpty()) {
    Node node = heap.poll();
    if (node.level == n) {       // 叶子
        // 第一个叶子即最优解
        break;
    }
    for (Node child : expand(node)) {
        if (feasible(child) && promising(child))
            heap.add(child);
    }
}
```

### 特点

- 优先扩展“最有希望”的结点，通常能更快到达叶子、更新 `cBest`；
- 第一个被取出的叶子就是最优解（见 8.1 节）；
- 需要为每个结点计算界，计算量比 FIFO 大；
- 空间仍可能很大，但实践中常比 FIFO 小。

::: warning 优先队列的“界”必须可比较
不同层的结点，其界必须是同一量纲（都是“从该结点出发能得到的最终目标值”），否则优先队列的顺序没有意义。例如 0-1 背包中，所有结点的 $UB$ 都表示“最终总价值的上界”，可以直接比较。
:::

## 8.2.6 策略三：LIFO 栈式

把队列换成栈，就得到类似深度优先的搜索。它空间较小，但失去了“按层推进”和“优先扩展好结点”的优点，实际很少单独使用。考试中若出现，通常是为了对比三种策略的搜索顺序。

| 策略 | 数据结构 | 搜索顺序 | 空间 | 找到第一个叶子的质量 |
| :--- | :--- | :--- | :--- | :--- |
| FIFO | 队列 | 广度优先 | 大 | 不一定最优 |
| 优先队列 | 堆 | 最佳优先 | 中到大 | 最优（按界定义） |
| LIFO | 栈 | 深度优先 | 小 | 不一定最优 |

## 8.2.7 搜索策略对剪枝的影响

以 0-1 背包为例，假设当前已有一个可行解 `best=65`：

- **FIFO**：按层扩展，可能在很深的地方才找到第一个可行解，之前所有结点都无法用 `best` 剪枝；
- **优先队列**：优先扩展 $UB$ 大的结点，很快到达一个高质量叶子，`best` 迅速提高，后续大量结点的 $UB$ 小于 `best`，被剪掉。

::: info 一个直观的对比
想象你在寻宝。FIFO 像“把地图上每一行都走一遍”，优先队列像“先去最可能有宝藏的地方”。虽然后者不一定保证少走路，但通常能更早找到宝贝，从而放弃更多明显没戏的区域。
:::

## 8.2.8 界的质量与算法性能

分支限界法的性能几乎完全取决于界：

| 界的情况 | 后果 |
| :--- | :--- |
| 界很紧 | 大量结点被剪，接近多项式时间 |
| 界很松 | 退化为穷举，指数时间 |
| 界计算太贵 | 单结点开销大，得不偿失 |
| 界不正确 | 可能剪掉最优解，结果错误 |

判断界的好坏，工程上常用**随机实例 + 运行时间/结点数统计**；理论上则分析界的近似比或与最优值的差距。

::: tip 多个界怎么用？
若有多个上界 $UB_1,UB_2,\dots$，取

$$UB=\min\{UB_1,UB_2,\dots\}$$

（越小越紧）；若有多个下界，取

$$LB=\max\{LB_1,LB_2,\dots\}$$

（越大越紧）。但要注意：每个界都必须单独有效，取 min/max 后才仍然有效。
:::

## 8.2.9 回溯法还是分支限界法？

| 场景 | 推荐 |
| :--- | :--- |
| 求所有可行解 | 回溯法 |
| 求一个可行解，约束很强 | 回溯法 |
| 求最优解，界容易计算 | 分支限界法 |
| 内存受限 | 回溯法 |
| 希望尽快得到一个好解 | 分支限界法（优先队列） |
| 解空间树很宽、很深 | 分支限界法 + 强界 |

::: warning 分支限界法不是“更高级的回溯法”
两者是并列的搜索策略，没有绝对的优劣。回溯法空间省、实现简单；分支限界法在“求最优解 + 界紧”时更快，但空间可能爆炸。考试中若题目要求“用分支限界法”，就不要写递归回溯；反之亦然。
:::
