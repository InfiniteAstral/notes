# 6.1 贪心法的基本思想与正确性证明

## 6.1.1 什么是贪心法

**贪心法（Greedy Method）在每一步决策时，都选择当前状态下看起来最优的选择**，并且做出选择后**不再更改**。它不试图考察所有可能的决策序列，而是希望“每一步都选局部最优，最终就能得到全局最优”。

用一句话概括：

> 贪心法 = **局部最优选择 + 不回退 + 期望全局最优**。

典型的贪心问题：

| 问题 | 贪心策略 |
| :--- | :--- |
| 活动安排 | 每次选结束时间最早的活动 |
| 分数背包 | 每次选单位重量价值最高的物品 |
| 最优装载 | 每次选最轻的集装箱 |
| 哈夫曼编码 | 每次合并频率最小的两棵树 |
| 最小生成树 | 每次选连接两个连通分量的最小边 |
| 单源最短路 | 每次选当前距离最小的未确定顶点 |
| 多机调度 | 每次把最长的作业分给当前负载最小的机器 |

## 6.1.2 适用条件

贪心法能得到全局最优，需要同时满足两个性质：

### （1）贪心选择性质

**所求问题的整体最优解，可以通过一系列局部最优的选择（贪心选择）达到**。也就是说，做出当前看起来最好的选择后，原问题仍然可以归结为一个规模更小的同类子问题。

### （2）最优子结构

**问题的最优解包含其子问题的最优解**。这与动态规划的要求相同。

::: warning 两个条件缺一不可
- 只有贪心选择性质、没有最优子结构：无法递归地保证后续选择；
- 只有最优子结构、没有贪心选择性质：局部最优可能把全局最优“堵死”，必须用动态规划比较所有决策。

0-1 背包就是典型的“有最优子结构、无贪心选择性质”的问题：按单位价值贪心可能选中一个占空间的大件，导致剩余容量装不下更高总价值的组合。
:::

## 6.1.3 贪心与动态规划的区别

| 维度 | 贪心法 | 动态规划 |
| :--- | :--- | :--- |
| 决策方式 | 每步只做一个选择，不回头 | 每个状态比较所有决策 |
| 求解方向 | 自顶向下（逐步缩小问题） | 自底向上（或记忆化） |
| 是否保留子问题解 | 不保留 | 保留所有相关子问题的解 |
| 正确性依据 | 贪心选择性质 + 最优子结构 | 最优子结构 + 无后效性 |
| 时间复杂度 | 通常 $O(n\log n)$ 或 $O(n)$ | 通常 $O(n^2)$、$O(n^3)$ 或 $O(nc)$ |
| 典型问题 | 活动安排、Huffman、MST | 矩阵连乘、背包、LCS |

::: tip 一个直观的比喻
- **贪心**像走迷宫时“只往看起来离出口最近的方向走”，走得快，但可能走进死胡同；
- **动态规划**像把迷宫每个位置到出口的最短路径都算出来，保证最优，但计算量大；
- **回溯/分支限界**像把所有路都走一遍（带剪枝），保证找到解，但最坏情况是指数级。
:::

## 6.1.4 正确性证明：交换论证

贪心算法最难的不是写，而是证明。最常用的方法是**交换论证（exchange argument）**：

1. 假设存在一个最优解 $O$，它与贪心解 $G$ 在某个位置首次不同；
2. 把 $O$ 中的那个选择“交换”成贪心的选择，得到 $O'$；
3. 证明 $O'$ 仍然是最优的（目标值不变差）；
4. 重复交换，最终把 $O$ 变成 $G$，说明 $G$ 也是最优的。

另一种常见方法是**归纳法**：证明第一步贪心选择可以包含在某个最优解中，然后对剩余子问题归纳。

## 6.1.5 例：活动安排问题

### 问题

设有 $n$ 个活动的集合 $E=\{1,2,\dots,n\}$，每个活动 $i$ 都有一个要求使用同一资源的时段 $[s_i,f_i)$。若 $[s_i,f_i)$ 与 $[s_j,f_j)$ 不重叠，则称活动 $i$ 与 $j$ **相容**。求最大的相容活动子集。

### 贪心策略

**每次选择结束时间最早、且与已选活动相容的活动。**

为什么不是“开始最早”或“持续时间最短”？

- 开始最早：可能选了一个很长、很占时间的活动；
- 持续时间最短：可能选了一个夹在中间、把两边都挡住的活动；
- 结束最早：留给后面的时间最多，最“不亏”。

### 算法

```text
greedyActivitySelector(s, f, n)
// s[1..n] 开始时间，f[1..n] 结束时间，且 f[1] ≤ f[2] ≤ … ≤ f[n]
A ← {1}
k ← 1
for m ← 2 to n
    if s[m] ≥ f[k]          // 与上一个已选活动相容
        A ← A ∪ {m}
        k ← m
return A
```

```java
List<Integer> select(int[] s, int[] f, int n) {
    List<Integer> a = new ArrayList<>();
    a.add(0);
    int k = 0;
    for (int m = 1; m < n; m++)
        if (s[m] >= f[k]) {
            a.add(m);
            k = m;
        }
    return a;
}
```

时间复杂度主要花在按结束时间排序：$O(n\log n)$；若输入已有序，则 $O(n)$。

### 正确性证明

::: details 交换论证
设 $f_1\le f_2\le\cdots\le f_n$。显然存在一个最优解包含活动 $1$（结束最早的活动）：若最优解的第一个活动是 $k\ne1$，由于 $f_1\le f_k$，把 $k$ 换成 $1$ 不会与后续活动冲突，解的大小不变。

因此，存在最优解 $A^*$ 包含活动 $1$。令 $A'$ 为 $A^*$ 去掉活动 $1$ 后，在“开始时间不早于 $f_1$”的活动集合上的最优解。由最优子结构，$A^*=\{1\}\cup A'$，且 $A'$ 是该子问题的最优解。

对子问题重复上述论证，可知贪心算法每一步的选择都包含在某个最优解中。归纳得贪心解是最优解。
:::

::: warning 排序是前提
上面的算法假设活动已按结束时间升序排列。若未排序，必须先排序，否则“选第一个相容活动”并不等于“选结束最早的活动”，贪心就失效了。
:::

## 6.1.6 贪心失效的经典反例

### 反例一：0-1 背包

物品：$(w,v)=(10,60),(20,100),(30,120)$，容量 $50$。

按单位价值排序：$6,5,4$。贪心先装物品 1（价值 $60$，剩 $40$），再装物品 2（价值 $100$，剩 $20$），总价值 $160$。

但最优解是装物品 2 和 3：重量 $50$，价值 $220$。

**原因**：0-1 背包的物品不可分割，贪心选了一个“性价比高但占地方”的物品，导致剩余容量浪费。

### 反例二：硬币找零

硬币面值 $\{1,5,11\}$，要找 $15$。贪心（每次取最大面值）得到 $11+1+1+1+1$，共 $5$ 枚；最优是 $5+5+5$，共 $3$ 枚。

**原因**：贪心选择性质不成立。面值系统必须满足特定条件（如人民币的 $1,2,5,10,20,50,100$）时，贪心才正确。

::: tip 如何判断能不能贪心
1. 先尝试构造反例：小规模、极端数据、边界情况；
2. 若找不到反例，尝试用交换论证证明；
3. 若证明卡住，很可能是贪心选择性质不成立，应改用动态规划；
4. 对于 NP 难问题，贪心通常只能得到近似解，需要给出近似比。
:::

## 6.1.7 贪心算法的设计步骤

1. **建模**：把问题转化为“选择一组对象/一个排列/一个划分”；
2. **确定贪心指标**：按什么排序？结束时间、单位价值、频率、边长……
3. **证明贪心选择性质**：用交换论证说明第一步贪心选择可纳入最优解；
4. **证明最优子结构**：说明做出贪心选择后，剩余问题是同类型的子问题；
5. **设计算法**：排序 + 线性扫描 / 优先队列；
6. **分析复杂度**：排序 $O(n\log n)$，扫描 $O(n)$，堆操作 $O(\log n)$。
