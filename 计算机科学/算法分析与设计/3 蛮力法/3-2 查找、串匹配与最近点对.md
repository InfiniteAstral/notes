# 3.2 查找、串匹配与最近点对

## 3.2.1 顺序查找

问题：在给定序列中查找某个固定值（查找键）。

最直接的做法是从头到尾逐个比较：

```text
sequentialSearch(A[0..n-1], key)
for i ← 0 to n-1
    if A[i] = key return i
return -1
```

| 情况 | 比较次数 | 复杂度 |
| :--- | :--- | :--- |
| 最好（第一个就是） | $1$ | $O(1)$ |
| 最坏（不存在） | $n$ | $O(n)$ |
| 平均（等概率） | $(n+1)/2$ | $O(n)$ |

::: tip 哨兵技巧
把 `key` 放到数组末尾作为“哨兵”，循环体内就省去 `i < n` 的边界判断：

```text
A[n] ← key
i ← 0
while A[i] ≠ key i ← i + 1
if i < n return i else return -1
```

这样每轮少一次比较，常数因子约减半。代价是需要数组多留一个位置。
:::

### 找最大值

```text
maxElement(A[0..n-1])
maxval ← A[0]
for i ← 1 to n-1
    if A[i] > maxval maxval ← A[i]
return maxval
```

恰好需要 $n-1$ 次比较。这不仅是上界，也是**下界**：除了最大值以外的 $n-1$ 个元素，每个都必须“输掉”至少一次比较，否则无法确认最大值。因此该算法在比较模型下是最优的。

## 3.2.2 串匹配

问题：给定长度为 $n$ 的文本 $T[0..n-1]$ 和长度为 $m$（$m\le n$）的模式 $P[0..m-1]$，找出 $P$ 在 $T$ 中第一次出现的位置。

蛮力思想：把模式对准文本的前 $m$ 个字符，从左到右逐对比较；一旦失配，模式右移一位，重新从头比较；若 $m$ 个字符全部匹配，则查找成功。

```text
bruteForceStringMatch(T[0..n-1], P[0..m-1])
for i ← 0 to n-m
    j ← 0
    while j < m and P[j] = T[i+j]
        j ← j + 1
    if j = m return i
return -1
```

注意最后一轮匹配的起始位置是 $n-m$，因为再往后文本剩余长度不足 $m$。

### 一个“最坏情况”的例子

设 $T=\text{ABABABABC}$，$P=\text{ABABC}$：

| 起始位置 $i$ | 对齐情况 | 比较次数 | 结果 |
| :--- | :--- | :--- | :--- |
| 0 | `ABABA` vs `ABABC` | 5 | 末位失配 |
| 1 | `BABAB` vs `ABABC` | 1 | 首位失配 |
| 2 | `ABABA` vs `ABABC` | 5 | 末位失配 |
| 3 | `BABAC` vs `ABABC` | 1 | 首位失配 |
| 4 | `ABABC` vs `ABABC` | 5 | 匹配成功 |

前几轮已经比较过的 `ABAB` 被反复比较，做了大量无用功。

### 复杂度

最坏情况下，每一轮都要比较 $m$ 次，共 $n-m+1$ 轮：

$$T_{\max}(n,m)=(n-m+1)m=O(nm)$$

当 $m\approx n/2$ 时达到 $\Theta(n^2)$。典型的坏输入是 $T=\underbrace{aa\cdots a}_{n}$、$P=\underbrace{aa\cdots a}_{m-1}b$。

平均情况下，若字符集大小为 $\sigma$、文本随机，则每次失配平均只比较 $O(1)$ 个字符，总复杂度接近 $O(n)$。但**最坏情况无法回避**。

::: info 从蛮力到 KMP
蛮力法的问题在于：失配后模式只右移一位，已经匹配的信息全部丢弃。KMP 算法利用模式自身的**前缀函数**，失配时把模式“滑动”到下一个可能匹配的位置，做到主串指针不回溯，时间复杂度 $O(n+m)$。Rabin–Karp 则用滚动哈希把每次比较降到 $O(1)$，平均 $O(n+m)$。
:::

## 3.2.3 最近点对问题

问题：在包含 $n$ 个点的平面点集中，找出距离最近的两个点。点 $P_i=(x_i,y_i)$ 与 $P_j=(x_j,y_j)$ 之间的欧氏距离为

$$d(P_i,P_j)=\sqrt{(x_i-x_j)^2+(y_i-y_j)^2}$$

蛮力法：计算每一对点的距离，取最小值。为避免同一对点被算两次，只考虑 $i<j$：

```text
bruteForceClosestPoints(P[0..n-1])
dmin ← ∞
for i ← 0 to n-2
    for j ← i+1 to n-1
        d ← (x[i]-x[j])² + (y[i]-y[j])²
        if d < dmin
            dmin ← d; index1 ← i; index2 ← j
return index1, index2
```

::: tip 比较平方距离
计算过程中只比较 $(x_i-x_j)^2+(y_i-y_j)^2$，最后再开方。这样既避免了 $n(n-1)/2$ 次开方运算，又不影响大小关系（开方是单调函数）。
:::

点对总数为

$$\binom{n}{2}=\frac{n(n-1)}{2}$$

每次计算距离是 $O(1)$，因此 $T(n)=\Theta(n^2)$，空间 $O(1)$。

对于 $n=10^5$，点对数量约为 $5\times10^9$，在现代计算机上需要数秒到数十秒，难以接受。第 4 章会用分治法把它降到 $O(n\log n)$。

## 3.2.4 小结：蛮力法的适用边界

| 问题 | 蛮力复杂度 | 是否可接受 |
| :--- | :--- | :--- |
| 顺序查找 | $O(n)$ | 是（无序数据的最优选择） |
| 找最大值 | $O(n)$ | 是（比较模型下最优） |
| 串匹配 | $O(nm)$ | 短文本可以，长文本需 KMP |
| 最近点对 | $O(n^2)$ | 小规模可以，大规模需分治 |
| 排序 | $O(n^2)$ | 小规模可以，大规模需 $O(n\log n)$ |

蛮力法的价值不在于“快”，而在于“**稳**”：它几乎不会写错，能给出一个可信的基准答案，也是进一步优化的起点。优化一个算法时，最常用的方法就是先写出蛮力版本，再观察“哪些比较是重复的、哪些候选不可能成为解”，从而剪掉它们。
