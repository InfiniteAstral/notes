# 7.3 典型应用（一）：N 皇后、图着色、货郎担与批作业调度

## 7.3.1 N 皇后问题

### 问题与建模

在 $N\times N$ 的棋盘上放置 $N$ 个皇后，使任意两个皇后不在同一行、同一列、同一对角线。

- 解向量：$(x_1,x_2,\dots,x_N)$，$x_i$ 表示第 $i$ 行皇后所在的列；
- 显式约束：$x_i\in\{1,2,\dots,N\}$；
- 隐式约束：
  - 不同列：$x_i\ne x_j$；
  - 不同正对角线：$x_i-i\ne x_j-j$；
  - 不同反对角线：$x_i+i\ne x_j+j$。

后两条可以合并为 $|x_i-x_j|\ne|i-j|$。

### 递归实现

```java
class NQueen {
    int n, sum = 0;
    int[] x;

    boolean check(int t) {
        for (int j = 1; j < t; j++)
            if (x[j] == x[t] || Math.abs(x[t] - x[j]) == Math.abs(t - j))
                return false;
        return true;
    }

    void backtrack(int t) {
        if (t > n) {
            sum++;
            return;
        }
        for (int i = 1; i <= n; i++) {
            x[t] = i;
            if (check(t)) backtrack(t + 1);
        }
    }
}
```

### 复杂度

搜索树是一棵 $n$ 叉树，最多有 $1+n+n^2+\cdots+n^n$ 个结点，上界 $O(n^n)$。由于剪枝，实际结点数远小于此。$n=8$ 时共有 $92$ 个解。

::: tip 用布尔数组或位运算加速判冲突
`check(t)` 每次要扫描前 $t-1$ 行，是 $O(n)$。可以用三个布尔数组（列、正对角线、反对角线）把判断降到 $O(1)$：

```java
boolean[] col, diag1, diag2;   // diag1: r-c+n, diag2: r+c
void backtrack(int t) {
    if (t > n) { sum++; return; }
    for (int i = 1; i <= n; i++) {
        if (col[i] || diag1[t - i + n] || diag2[t + i]) continue;
        col[i] = diag1[t - i + n] = diag2[t + i] = true;
        x[t] = i;
        backtrack(t + 1);
        col[i] = diag1[t - i + n] = diag2[t + i] = false;
    }
}
```

这是“用空间换时间”的典型：把 $O(n)$ 的冲突检查降到 $O(1)$，整体性能提升一个数量级。位运算版本还能进一步把三个数组压成三个整数。
:::

## 7.3.2 图的 $m$ 着色问题

### 问题

给定无向连通图 $G=(V,E)$ 和 $m$ 种颜色。用这些颜色为每个顶点着色，要求每条边的两个顶点颜色不同。问是否存在一种着色方案？若一个图最少需要 $m$ 种颜色，则称 $m$ 为该图的**色数**。

- 判定问题：给定 $m$，是否存在合法着色？
- 优化问题：求最小的 $m$。

平面图的四色定理告诉我们：任何平面图都可用 $4$ 种颜色着色。但一般图的着色是 NP 难的。

### 建模

- 解向量：$(x_1,x_2,\dots,x_n)$，$x_i\in\{1,\dots,m\}$ 表示顶点 $i$ 的颜色；
- 隐式约束：若 $(i,j)\in E$，则 $x_i\ne x_j$。

### 算法

```java
class Coloring {
    int n, m, sum = 0;
    int[] x;
    boolean[][] a;              // 邻接矩阵

    boolean ok(int t) {
        for (int j = 1; j < t; j++)
            if (a[t][j] && x[j] == x[t]) return false;
        return true;
    }

    void backtrack(int t) {
        if (t > n) {
            sum++;
            // 输出 x[1..n]
            return;
        }
        for (int i = 1; i <= m; i++) {
            x[t] = i;
            if (ok(t)) backtrack(t + 1);
            x[t] = 0;           // 恢复现场
        }
    }
}
```

::: info `ok(t)` 为什么只检查 $j<t$？
顶点按 $1..n$ 顺序着色，第 $t$ 个顶点着色时，$j>t$ 的顶点还没着色（$x_j=0$），不可能与 $x_t$ 冲突。因此只需检查已着色的前 $t-1$ 个顶点。若写成 `j=1..n`，虽然结果正确，但多做无用功。
:::

### 复杂度

搜索树是一棵 $m$ 叉树，最坏 $O(m^n)$。剪枝效果取决于图的结构：边越密，冲突越早出现，剪枝越强。

::: tip 优化：按度数从大到小着色
先给度数大的顶点着色，可以更早触发冲突，减少搜索量。这不会改变最坏复杂度，但通常能显著加速。另一种优化是**对称性消除**：第一个顶点固定为颜色 $1$，避免颜色编号的 $m!$ 种重复。
:::

## 7.3.3 货郎担问题（TSP）

### 问题

某售货员要从驻地出发，经过每个城市恰好一次，最后回到驻地，使总路程最短。给定 $n$ 个城市及两两之间的距离矩阵 $a$，求一条最优回路。

- 解向量：$(x_1,x_2,\dots,x_n)$，表示访问顺序，$x_1=1$；
- 显式约束：$x_i\in\{1,\dots,n\}$；
- 隐式约束：$x_i$ 互不相同，$(x_i,x_{i+1})\in E$，$(x_n,x_1)\in E$。

解空间是一棵**排列树**，叶子数 $(n-1)!$。

### 带剪枝的回溯

维护：

- `cc`：当前路径长度；
- `bestc`：当前最优路径长度；
- `x[1..n]`：当前路径；
- `bestx[1..n]`：最优路径。

```java
void backtrack(int t) {           // t 从 2 开始，x[1]=1
    if (t == n) {
        if (a[x[n - 1]][x[n]] != NoEdge && a[x[n]][1] != NoEdge
            && (cc + a[x[n - 1]][x[n]] + a[x[n]][1] < bestc || bestc == NoEdge)) {
            for (int j = 1; j <= n; j++) bestx[j] = x[j];
            bestc = cc + a[x[n - 1]][x[n]] + a[x[n]][1];
        }
    } else {
        for (int j = t; j <= n; j++) {
            if (a[x[t - 1]][x[j]] != NoEdge
                && (cc + a[x[t - 1]][x[j]] < bestc || bestc == NoEdge)) {
                swap(x[t], x[j]);
                cc += a[x[t - 1]][x[t]];
                backtrack(t + 1);
                cc -= a[x[t - 1]][x[t]];   // 恢复现场
                swap(x[t], x[j]);
            }
        }
    }
}
```

::: warning 两个剪枝条件
1. **可行性**：`a[x[t-1]][x[j]] != NoEdge`，即两个城市之间有边；
2. **最优性**：`cc + a[x[t-1]][x[j]] < bestc`，若当前路径已经不比最优解短，就没必要继续。

第二个条件是“界函数”的雏形：当前路径长度是最终回路长度的**下界**，若下界已经不小于 `bestc`，整棵子树都可以剪掉。
:::

### 复杂度

最坏情况下需要更新最优解 $O((n-1)!)$ 次，每次复制路径 $O(n)$，总复杂度 $O(n!)$。加入剪枝后，实际搜索量通常远小于 $n!$，但最坏仍是指数级。

::: tip 更强的下界
`cc` 只是“已走路径”，还没有考虑“回到起点”和“剩余城市”。更好的下界是：

$$\text{lb}=cc+\text{剩余城市的最小生成树权值}+\text{当前点到剩余部分的最小边}+\text{终点到起点最小边}$$

下界越紧，剪枝越强。第 8 章的分支限界法会系统使用这类下界。
:::

## 7.3.4 批作业调度问题

### 问题

给定 $n$ 个作业 $\{J_1,\dots,J_n\}$，每个作业必须先由机器 1 处理，再由机器 2 处理。所有作业在机器 2 上完成处理的时间之和称为**完成时间和**。求最佳调度方案，使完成时间和最小。

解空间是排列树：作业的加工顺序。

### 完成时间的计算

设当前调度序列为 $\langle x_1,\dots,x_t\rangle$，令：

- $f_1$：机器 1 上最后一个作业的完成时间；
- $f_2$：机器 2 上最后一个作业的完成时间；
- $sf_2$：目前所有作业在机器 2 上的完成时间之和。

加工第 $t$ 个作业 $j$ 时：

$$f_1\leftarrow f_1+t_{1j},\qquad f_2\leftarrow \max\{f_1,\ f_2\}+t_{2j},\qquad sf_2\leftarrow sf_2+f_2$$

### 回溯实现

```java
void backtrack(int t) {
    if (t > n) {
        if (sf2 < bestc) {
            bestc = sf2;
            bestx = x.clone();
        }
        return;
    }
    for (int i = t; i <= n; i++) {
        swap(x[t], x[i]);
        f1 += t1[x[t]];
        int oldF2 = f2;
        f2 = Math.max(f1, f2) + t2[x[t]];
        sf2 += f2;

        if (sf2 < bestc) backtrack(t + 1);   // 界剪枝

        sf2 -= f2;
        f2 = oldF2;
        f1 -= t1[x[t]];
        swap(x[t], x[i]);
    }
}
```

### 剪枝

由于每个作业的完成时间都是正数，若当前 $sf_2$ 已经不小于已知最优值 `bestc`，继续加工只会让 $sf_2$ 更大，可以立即剪枝。

```java
if (sf2 >= bestc) return;   // 更早剪枝
```

::: tip 更强的下界
`sf2` 只算了已加工作业，没算剩余作业。可以为剩余作业估计一个“理想完成时间和”：

- 假设机器 1 无空闲，剩余作业按 $t_1$ 升序紧凑加工；
- 假设机器 2 也无空闲，按 $t_2$ 升序紧凑加工；
- 取两种估计的较大者作为剩余代价的下界。

若 `sf2 + 下界 >= bestc`，即可剪枝。这就是分支限界法中批作业调度的下界函数。
:::

### 复杂度

排列树有 $n!$ 个叶子，最坏 $O(n!)$。剪枝后实际搜索量取决于数据；若加工时间差异大，剪枝效果明显。

## 7.3.5 四个问题的对比

| 问题 | 解空间树 | 解向量含义 | 约束/界 | 最坏复杂度 |
| :--- | :--- | :--- | :--- | :--- |
| N 皇后 | $n$ 叉树 | 每行皇后所在列 | 列、对角线冲突 | $O(n^n)$ |
| 图 $m$ 着色 | $m$ 叉树 | 每个顶点的颜色 | 相邻顶点不同色 | $O(m^n)$ |
| 货郎担 | 排列树 | 城市访问顺序 | 边存在、路径长度上界 | $O(n!)$ |
| 批作业调度 | 排列树 | 作业加工顺序 | 完成时间和上界 | $O(n!)$ |

::: info 一个有趣的变体：高精度数
构造一个尽可能大的数 $a_1a_2\cdots a_n$，使前 $1$ 位能被 $1$ 整除、前 $2$ 位能被 $2$ 整除……前 $n$ 位能被 $n$ 整除。

解向量是每一位的数字，显式约束 $a_i\in\{0,\dots,9\}$，隐式约束是“前缀数能被长度整除”。搜索时从高位到低位，每加一位就检查整除性，不满足立即回溯。这是一个典型的“逐位构造 + 约束剪枝”问题，与 N 皇后的框架完全一致。
:::
