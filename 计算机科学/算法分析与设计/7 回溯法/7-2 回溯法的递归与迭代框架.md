# 7.2 回溯法的递归与迭代框架

## 7.2.1 递归框架

回溯法最自然的实现是递归。设解向量为 $x[1..n]$，当前正在确定第 $t$ 位：

```c
void backtrack(int t) {
    if (t > n)
        output(x);                       // 得到一个完整解
    else
        for (int i = f(n, t); i <= g(n, t); i++) {
            x[t] = h(i);                 // 第 t 位取第 i 个可选值
            if (constraint(t) && bound(t))
                backtrack(t + 1);        // 扩展下一位
        }
}
```

各部分的含义：

| 符号 | 含义 | 常见取值 |
| :--- | :--- | :--- |
| $t$ | 当前扩展的层数（已确定前 $t-1$ 位） | $1\sim n$ |
| $f(n,t)$ | 第 $t$ 层可选值的起始编号 | 子集树为 $0$，排列树为 $t$，$m$ 叉树为 $1$ |
| $g(n,t)$ | 第 $t$ 层可选值的终止编号 | 子集树为 $1$，排列树为 $n$，$m$ 叉树为 $m$ |
| $h(i)$ | 第 $i$ 个可选值的实际取值 | 通常就是 $i$ |
| `constraint(t)` | 约束函数：当前部分解是否可行 | 列冲突、容量约束、边存在 |
| `bound(t)` | 界函数：当前部分解是否可能优于已知最优 | 上界/下界剪枝 |
| `output(x)` | 输出或更新最优解 | 计数、保存解向量 |

::: warning `bound` 只用于优化问题
若问题是“求所有可行解”（如 N 皇后计数），只需要 `constraint`；若问题是“求最优解”（如 0-1 背包、TSP），才需要 `bound`。把 `bound` 误用于“求所有解”，会漏掉一些可行解。
:::

## 7.2.2 例：N 皇后的递归实现

```java
class Queen {
    int n, sum = 0;
    int[] x;                       // x[1..n]

    boolean check(int t) {
        for (int j = 1; j < t; j++)
            if (x[j] == x[t] || Math.abs(x[t] - x[j]) == Math.abs(t - j))
                return false;
        return true;
    }

    void backtrack(int t) {
        if (t > n) {
            sum++;                 // 找到一个解
        } else {
            for (int i = 1; i <= n; i++) {
                x[t] = i;
                if (check(t)) backtrack(t + 1);
            }
        }
    }
}
```

- 第 $t$ 层决定第 $t$ 行皇后放在哪一列；
- `check(t)` 只检查前 $t-1$ 行，因为后面的行还没放；
- 找到一个解后 `sum++`，然后自动返回上一层继续尝试。

对于 $n=8$，解的总数为 $92$。算法的最坏上界是 $O(n^n)$，但由于剪枝，实际访问的结点数远小于 $n^n$。

## 7.2.3 迭代框架

递归的缺点是函数调用开销和栈深度限制。迭代框架用数组 $f[t]$ 记录第 $t$ 层“下一个要尝试的值”，手动模拟回溯：

```java
void iterativeBacktrack(int n) {
    int t = 1;
    int[] f = new int[n + 1];
    Arrays.fill(f, 1);                 // 每层从 1 开始
    while (t > 0) {
        if (f[t] <= n) {
            x[t] = f[t];
            if (constraint(t) && bound(t)) {
                if (t == n) {
                    output(x);
                    f[t]++;            // 同一层尝试下一个值
                } else {
                    t++;
                    f[t] = 1;          // 进入下一层，重置
                }
            } else {
                f[t]++;                // 当前值不合法，试下一个
            }
        } else {
            f[t] = 1;                  // 本层试完，重置后回溯
            t--;
            if (t > 0) f[t]++;         // 上一层换下一个值
        }
    }
}
```

### N 皇后的迭代版本

```java
void iterativeQueen(int n) {
    int t = 1, sum = 0;
    int[] f = new int[n + 1];
    int[] x = new int[n + 1];
    Arrays.fill(f, 1);
    while (t > 0) {
        if (f[t] <= n) {
            x[t] = f[t];
            if (check(t, x)) {
                if (t == n) {
                    sum++;
                    f[t]++;
                } else {
                    t++;
                    f[t] = 1;
                }
            } else {
                f[t]++;
            }
        } else {
            f[t] = 1;
            t--;
            if (t > 0) f[t]++;
        }
    }
}
```

::: tip 迭代版的三个易错点
1. **回溯后忘记重置 `f[t]`**：回到上一层时，下一层的 `f` 必须恢复为 $1$，否则下次进入会从旧值继续，漏解。
2. **叶子处理后忘记 `f[t]++`**：输出解后若不递增，会在同一层无限循环。
3. **`t--` 后忘记 `f[t]++`**：回溯到上一层后，必须换下一个值，否则会重复搜索同一分支。
:::

## 7.2.4 递归 vs 迭代

| 维度 | 递归 | 迭代 |
| :--- | :--- | :--- |
| 代码可读性 | 高，与解空间树结构一致 | 较低，需手动维护层与候选值 |
| 空间 | 递归栈 $O(n)$ | 显式数组 $O(n)$ |
| 栈溢出风险 | 深度大时可能溢出 | 无 |
| 调试难度 | 较低 | 较高，边界多 |
| 适用场景 | 绝大多数回溯问题 | 深度极大、对性能敏感 |

::: info 为什么教材还要讲迭代版？
一是为了说明“递归只是实现手段，回溯的本质是状态+栈”；二是考试中常要求“把递归改写为迭代”，考查对搜索过程的理解。实际工程中，除非深度极大，否则优先用递归。
:::

## 7.2.5 恢复现场

排列树与需要修改全局状态的回溯中，**递归返回后必须把状态恢复到进入本层时的样子**，否则后续分支会在被污染的状态上搜索。

以全排列为例：

```java
void permute(int[] a, int k, int n) {
    if (k == n) {
        System.out.println(Arrays.toString(a));
        return;
    }
    for (int i = k; i < n; i++) {
        swap(a, k, i);
        permute(a, k + 1, n);
        swap(a, k, i);          // 恢复现场
    }
}
```

::: details 不恢复现场会怎样？
设 $a=\{1,2,3,4,5\}$，在 $k=2$ 时依次把 $2,3,4,5$ 交换到第 $2$ 位。

- 搜索以 $1,3$ 开头的分支后，数组可能已经变成 $\{1,3,4,2,5\}$；
- 若不恢复，下一次想把 $4$ 换到第 $2$ 位，得到的却是 $\{1,3,2,4,5\}$——这是以 $1,3,2$ 开头的排列，前面已经搜过；
- 结果就是**部分分支重复搜索，部分分支永远搜不到**。

恢复现场后，每次交换都基于原始数组，才能保证不重不漏。
:::

需要恢复的常见状态：

- 交换过的数组元素；
- 当前重量 `cw`、当前价值 `cv`、当前路径长度 `cc`；
- 标记数组（`visited`、列占用、对角线占用）；
- 当前解向量 `x[t]`（有些框架依赖覆盖，不必显式恢复）。

## 7.2.6 剪枝函数的设计

剪枝函数分为两类：

| 类型 | 作用 | 典型形式 |
| :--- | :--- | :--- |
| 约束函数 `constraint` | 判断部分解是否**可行** | `cw + w[i] <= c`、`!colConflict`、`a[x[t-1]][x[t]] != ∞` |
| 界函数 `bound` | 判断部分解是否**可能更优** | `cw + r > bestw`、`cv + bound(i) > bestp`、`cc + minEdge < bestc` |

设计原则：

1. **越早剪越好**：能在高层判断的约束，不要拖到叶子；
2. **计算要便宜**：剪枝函数本身不能太贵，否则得不偿失；
3. **界要有效**：太松起不到剪枝作用，太紧可能算不出来；
4. **优先扩展“最可能成功”的分支**：例如 TSP 中先走代价小的边，可以更快得到一个好的下界，从而剪掉更多分支。

::: tip 一个常用的搜索顺序技巧
在每一层，先把候选值按“启发式好坏”排序，优先搜索更可能得到好解的分支。这样能更早更新 `best`，让界函数更早发挥作用。N 皇后中可以优先尝试中间列；TSP 中可以先走最短边。这不会改变最坏复杂度，但能显著改善平均性能。
:::

## 7.2.7 回溯法的效率因素

回溯算法的效率主要取决于：

1. **产生 $x[k]$ 的时间**；
2. **计算约束函数 `constraint` 的时间**；
3. **计算界函数 `bound` 的时间**；
4. **满足约束与界函数的结点个数**（搜索树的实际大小）。

前三条是“单结点开销”，第四条是“结点总数”。优化方向相应有两类：

- 降低单结点开销：用位运算判列/对角线冲突、用增量式计算重量与价值、用邻接矩阵 $O(1)$ 判边；
- 减少结点总数：更强的剪枝、更好的搜索顺序、对称性消除（如 N 皇后只搜前半列再对称计数）。

::: warning 最坏复杂度仍是指数
无论剪枝多好，回溯法的最坏复杂度仍是指数级。若问题规模很大且没有好的剪枝，应考虑：

- 分支限界法（更适合求最优解，能用优先队列快速找到好解）；
- 动态规划（若子问题重叠且状态可压缩）；
- 近似算法/启发式（若只要求可接受的解）。
:::
